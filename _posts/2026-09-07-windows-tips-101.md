Trong môi trường doanh nghiệp hiện đại, chuyên viên IT Support và Quản trị hệ thống (SysAdmin) thường xuyên phải đối mặt với các sự cố người dùng báo về: **"Máy tính không vào được mạng"**, **"Không mở được ứng dụng Microsoft 365 / Teams"**, hoặc **"Không thể kết nối vào máy chủ nội bộ qua VPN"**.

Thay vì hướng dẫn người dùng khởi động lại máy tính một cách thụ động, bài viết này sẽ trang bị cho bạn quy trình **5 bước chẩn đoán và xử lý sự cố chuẩn hóa (Standard Operating Procedure - SOP)** bằng PowerShell và công cụ dòng lệnh tích hợp sẵn trên Windows 11/Windows Server.

---

## 1. Kiểm tra trạng thái Network Adapter và IP Configuration

Bước đầu tiên luôn là xác minh card mạng vật lý hoặc card mạng ảo (Wi-Fi, Ethernet, VPN Adapter) có đang ở trạng thái `Up` và nhận đúng cấu hình DHCP hay không.

Mở PowerShell với quyền Quản trị viên (**Run as Administrator**) và thực thi:

```powershell
# 1. Liệt kê danh sách card mạng và tốc độ kết nối
Get-NetAdapter | Select-Object Name, InterfaceDescription, Status, LinkSpeed

# 2. Xem chi tiết địa chỉ IPv4, Default Gateway và DNS Server
Get-NetIPConfiguration | Format-Table InterfaceAlias, IPv4Address, IPv4DefaultGateway, DNSServer
```

> **Mẹo SysAdmin:** Nếu người dùng bị mất kết nối do lỗi driver card mạng tạm thời bị treo, bạn có thể khởi động lại adapter từ xa mà không cần rút cáp:
>
> ```powershell
> Restart-NetAdapter -Name "Wi-Fi"
> ```

## 2. Khắc phục sự cố phân giải tên miền (DNS Resolution)

Hơn 70% sự cố "mất mạng" trong doanh nghiệp thực chất là do **lỗi phân giải DNS** hoặc máy trạm nhận phải DNS cache cũ khi vừa chuyển đổi giữa mạng văn phòng và mạng làm việc tại nhà (WFA).

### Xóa sạch DNS Cache và tra cứu trực tiếp

```powershell
# Xóa bộ nhớ cache DNS trên máy trạm
Clear-DnsClientCache

# Kiểm tra bản ghi DNS tới máy chủ Microsoft Entra / Login Portal
Resolve-DnsName -Name "login.microsoftonline.com" -Type A

# Thử truy vấn qua máy chủ DNS công cộng của Google (8.8.8.8) hoặc Cloudflare (1.1.1.1)
Resolve-DnsName -Name "login.microsoftonline.com" -Server "1.1.1.1"
```

Nếu DNS của bên thứ ba phân giải được trong khi DNS máy trạm báo lỗi, hãy kiểm tra lại cấu hình DNS Server nội bộ hoặc dịch vụ DNS trên Domain Controller (AD DS).

## 3. Kiểm tra khả năng định tuyến cổng dịch vụ (Port Connectivity Test)

Lệnh `ping` truyền thống sử dụng giao thức ICMP, vốn thường xuyên bị chặn bởi Firewall doanh nghiệp hoặc Network Security Group (NSG) trên Azure Cloud. Để xác định chính xác một dịch vụ có mở cổng hay không, hãy dùng cmdlet `Test-NetConnection`:

```powershell
# Kiểm tra cổng HTTPS (Port 443) tới dịch vụ Exchange Online
Test-NetConnection -ComputerName "outlook.office365.com" -Port 443

# Kiểm tra kết nối RDP (Port 3389) tới máy chủ quản trị nội bộ
Test-NetConnection -ComputerName "192.168.10.50" -Port 3389
```

Kết quả trả về trường `TcpTestSucceeded : True` khẳng định đường truyền mạng và chính sách tường lửa hoàn toàn thông suốt.

## 4. Đặt lại toàn bộ Network Stack (Network Reset Triệt Để)

Khi máy tính người dùng gặp hiện tượng xung đột IP (IP Conflict), Winsock bị lỗi sau khi gỡ phần mềm Antivirus hoặc Proxy của bên thứ ba, bạn có thể chạy kịch bản làm sạch toàn bộ ngăn xếp giao thức mạng:

```powershell
# Đặt lại Winsock Catalog và TCP/IP Stack
netsh winsock reset
netsh int ip reset

# Giải phóng và xin cấp lại IP từ DHCP Server
ipconfig /release
ipconfig /renew
ipconfig /flushdns
```

*(Sau khi chạy các lệnh trên, bạn nên cho máy trạm khởi động lại để toàn bộ socket TCP/IP được khởi tạo lại mới hoàn toàn).*

## 5. Phục hồi tệp tin hệ điều hành bị hỏng (DISM & SFC)

Nếu lỗi mạng hoặc lỗi các dịch vụ hệ thống xuất phát từ việc các file `.dll` của Windows bị hỏng do tắt máy đột ngột hoặc xung đột cập nhật Windows Update, hãy chạy cặp lệnh sửa chữa kinh điển:

```powershell
# Bước 1: Kiểm tra và sửa chữa kho ảnh hệ điều hành Windows từ máy chủ Microsoft
DISM.exe /Online /Cleanup-image /Restorehealth

# Bước 2: Quét toàn bộ tệp tin hệ thống và tự động thay thế tệp bị lỗi
sfc /scannow
```

## 6. Chẩn đoán trạng thái gia nhập Cloud (Microsoft Entra ID / Intune)

Đối với các thiết bị doanh nghiệp được quản lý theo mô hình Hiện đại (Modern Workplace / Hybrid Azure AD Joined), khi người dùng không thể đăng nhập vào ứng dụng Microsoft 365, hãy kiểm tra trạng thái Token thiết bị:

```cmd
dsregcmd /status
```

Hãy chú ý các chỉ số quan trọng trong phần output:
- `AzureAdJoined : YES` (Thiết bị đã tham gia Azure AD)
- `IsUserAzureAD : YES` (Tài khoản người dùng đang đăng nhập là Entra ID)
- `WamDefaultSet : YES` (Web Account Manager hoạt động bình thường)

Hãy lưu lại trang web này hoặc đánh dấu mục **PowerShell Toolbox** để luôn có sẵn các câu lệnh hữu ích trong công việc thường nhật!
